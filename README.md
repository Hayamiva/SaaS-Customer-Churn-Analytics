# Анализ подписок и оттока клиентов стримингового сервиса (SaaS & Customer Churn Analytics)

## 📌 Описание проекта
Проект посвящен сквозному анализу поведения подписчиков, расчету ключевых продуктовых/финансовых метрик и визуализации динамики оттока (Churn Rate). 

**Цель проекта:** Спроектировать реляционную базу данных, рассчитать метрики удержания клиентов с помощью продвинутого SQL и построить интерактивный бизнес-дашборд в Power BI для поиска зон потери выручки.

**Технологический стек:** 
* **SQL (PostgreSQL):** DDL/DML, оконные функции, условная агрегация (CASE WHEN), JOIN.
* **Power BI:** Подключение к БД, построение схемы «Звезда» (1:*), расчет продвинутых мер на языке DAX (CALCULATE, VAR, DIVIDE), UI/UX дизайн отчета.

## 🗄️ 1. Архитектура данных и SQL-аналитика

Данные организованы по классической аналитической схеме **«Звезда» (Star Schema)**, что оптимизирует скорость работы аналитических запросов:
* `Fact_Subscriptions` — таблица фактов, содержащая историю подписок, даты начала/окончания и статусы.
* `Dim_Users` — справочник пользователей (география, возраст, дата регистрации).
* `Dim_Plans` — справочник тарифных планов стримингового сервиса и их стоимости.

### Ключевые аналитические SQL-запросы:

#### А) Расчет базовых продуктовых метрик
Запрос рассчитывает общее число клиентов, их средний возраст и текущую ежемесячную выручку (MRR) от активных подписчиков:
```sql
SELECT 
    (SELECT COUNT(User_ID) FROM Dim_Users) AS Total_Users,
    (SELECT AVG(Age) FROM Dim_Users) AS Avg_Age,
    SUM(p.Monthly_Price) AS Total_Active_Revenue
FROM Fact_Subscriptions s
JOIN Dim_Plans p ON s.Plan_ID = p.Plan_ID
WHERE s.Status = 'Active';
```
*Результат выполнения:* 5 пользователей; средний возраст — 29.6 лет; текущая выручка — 44.97.

#### Б) Анализ динамики доходов (Накопительный итог)
Использование оконных функций для расчета Running Total, чтобы отслеживать приток валовой выручки по мере регистрации клиентов:
```sql
SELECT 
    u.Registration_Date,
    u.User_ID,
    p.Monthly_Price,
    SUM(p.Monthly_Price) OVER (ORDER BY u.Registration_Date) AS Running_Total_Revenue
FROM Dim_Users u
JOIN Fact_Subscriptions s ON u.User_ID = s.User_ID
JOIN Dim_Plans p ON s.Plan_ID = p.Plan_ID;
```
*Результат выполнения:* Итоговый накопительный доход сервиса составил 69.95.

#### В) Расчет общего коэффициента оттока (Churn Rate)
Применение условной агрегации через `CASE WHEN` для вычисления процента клиентов, отменивших подписку:
```sql
SELECT 
    COUNT(User_ID) AS Total_Customers,
    SUM(CASE WHEN Status = 'Cancelled' THEN 1 ELSE 0 END) AS Churned_Customers,
    (SUM(CASE WHEN Status = 'Cancelled' THEN 1.0 ELSE 0 END) / COUNT(User_ID)) * 100 AS Churn_Rate_Percent
FROM Fact_Subscriptions;
```
*Результат выполнения:* Общий Churn Rate сервиса составляет 40%.

## 📊 2. Моделирование и визуализация в Power BI

Данные были импортированы напрямую из СУБД PostgreSQL. Внутри Power BI настроена правильная однонаправленная связь «один ко многим» (1:*) от справочников к таблице фактов.

Для чистоты архитектуры проекта все формулы вынесены в изолированную таблицу `_Measures`. Написаны продвинутые меры на языке DAX:
* **Total Customers** (Уникальное число клиентов): `DISTINCTCOUNT(Fact_Subscriptions[User_ID])`
* **Churn Rate %** (Коэффициент оттока с безопасным делением через переменные):
  ```dax
  Churn Rate % = 
  VAR ChurnedCustomers = CALCULATE([Total Customers], Fact_Subscriptions[Status] = "Cancelled")
  RETURN
  DIVIDE(ChurnedCustomers, [Total Customers], 0)
  ```

### 🧠 3. Ключевые бизнес-инсайты (Data Insights)

На основе интерактивного дашборда были выявлены критические паттерны в поведении клиентов:
1. **Географический отток:** Общий уровень оттока составляет **40%**. При этом детальный анализ по странам показал, что Churn Rate в **Австралии составляет 100%** (все клиенты отменили подписку), в то время как в **России отток равен 0%** (клиенты остаются активными). Сервису необходимо срочно локализовать контент или проверить стабильность платежных шлюзов для австралийского региона.
2. **Анализ тарифных планов:** 
   * Тарифы **Basic** и **Standard** имеют высокий уровень оттока — **50%**.
   * Тариф **Premium** удерживает клиентов идеально — **0% оттока**. Пользователи самого дорогого тарифа наиболее лояльны. Стратегическое решение: пересмотреть ценность базовых пакетов или сделать упор на продвижение Premium-подписки.
